# 交棒收尾口令

一棒结束、切模型、上下文将满、或准备离开前，把下面整段发给当前模型。

---

请先停手，不要再开新的功能或新的探索。按下面收尾，然后把更新后的文件路径发还给我：

1. **先归档，再重写现场。** 若 `HANDOFF.md` 已有上一棒内容，先复制到 `logs/handoff-archive/YYYYMMDD-HHMM-handoff.md`（时间用 America/Cordoba），然后再把 `HANDOFF.md` 整份重写为当前现场：本棒做了什么、改了哪些文件、下一步的第一个动作、不要做的事，以及本棒的 Trace / Distill / Prune 摘要。不要把本文件写成流水账。
2. 更新 `STATE.md` 的当前主线、认领状态和一句话状态。删掉已经过时的主线描述和过期约束。若本棒结束，释放认领。
3. 更新 `tasks.json` 或 `TASKS.md`：只改状态、认领、证据和验证字段。已完成项必须写清「已实测」或「未实测」，并给出复验命令或产物路径。未实测的不得标 done。
4. 若有新的决策、被否决的路径，或发现 `AGENTS.md` / `STATE.md` 里有失效、重复、冲突的条款：追加到 `DECISIONS.md` 的 `N-xxx`，写清为何失效和替代结论。不要改写旧条目。
5. **Prune：** 列出建议从 `AGENTS.md` 删除或替换的条款，以及对应的 `N-xxx`。未经我确认，不要直接改 `AGENTS.md`。我确认后，再删除入口文件中的旧条款，不要只追加新规则而留下旧规则。
6. 若是 Git 项目：给出 `git status`、当前分支、HEAD，以及是否已提交。不要在我未要求时推远程或开 PR。

最后用五句话总结：完成了什么、验证了什么、没做完什么、阻塞是什么、下一棒第一件事是什么。另外用一两句说明：归档了哪份旧现场、是否有待我确认的规则晋升或退役。
