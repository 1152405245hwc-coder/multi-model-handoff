# AGENTS.md

这是给所有编码 / 内容 Agent 的稳定契约，不是给人类看的 README 替代品。项目目标、命令、边界和交接规则写在这里；会话过程中的活状态写在 `STATE.md` / `HANDOFF.md`，不要把短期进度塞进本文件。

本文件只准**替换**已有条款，或把已验证经验经**人工确认后晋升**进来，**不准无限追加**。过时、冲突或不再适用的条款必须先退役到 `DECISIONS.md` 的 `N-xxx`（含「已退役规则 / Lessons Retired」），再从本文件删除或改写，不要把新旧结论叠在一起。

## 北极星与阅读顺序

开场必须先读，且按这个顺序：

1. 本文件（稳定规则）
2. `STATE.md`（当前唯一主线、范围边界、认领状态）
3. `DECISIONS.md`（已采纳决策 + 已否决 / 已退役路径，禁止重走）
4. `HANDOFF.md`（上一棒交出来的当前现场；不是历史流水账）
5. `tasks.json` 或 `TASKS.md`（若存在）
6. 真实代码、产物路径和实测记录；聊天记录不是真相

不要把 `logs/handoff-archive/` 里的旧交接当作当前事实。

若以上文件互相冲突：以 `STATE.md` 的北极星和范围边界为准，以 `DECISIONS.md` 的否决与退役记录为准，不要自行“重新规划主线”。需要改主线时，先停下来问项目负责人。

## 硬规则

- 同一时间只推进 `STATE.md` 里的**一条主线任务**。没有认领，就不要改文件。
- 先看 `DECISIONS.md` 的否决区与已退役规则。已经被否决或退役的方案，禁止换个说法再做一遍。
- 不要覆盖别人正在改的文件。若 `STATE.md` 显示该路径已被其他模型认领，退出并改做未认领任务，或等项目负责人改派。
- 不要把“写完代码 / 写完文案”标成完成。完成必须附可复验证据：命令、退出码、产物路径、截图或日志路径，并标明 **已实测** 或 **未实测**。
- 发现偏离北极星、超出“不做清单”，或要把已否决路径翻案：冻结改动，写入 `HANDOFF.md` 的待决问题，交给项目负责人。
- `DECISIONS.md` 只追加，不改写历史条目。需要更正时新增一条“更正”。`HANDOFF.md` 每次交棒整份重写为当前现场，旧现场先归档，再覆盖。
- 未经项目负责人确认，不要改写本文件。若发现本文件与代码或现场冲突，在 `HANDOFF.md` 提出替换 / 退役草案，等确认后再改。

## 规则演进（Trace → Distill → Prune）

这是每棒都要遵守的低成本清理节奏，不是单独的重型框架。

1. **Trace（留痕）**：把尝试、关键决策、失败原因、验证结果和为何改向记下来。活证据写进当次 `HANDOFF.md`；交棒重写前，把上一份 `HANDOFF.md` 追加归档到 `logs/handoff-archive/`。长期决策与否决只追加到 `DECISIONS.md`。
2. **Distill（提炼）**：只把已经验证、且会反复出现的规律、约束和可复用流程，做成准备晋升进本文件的短条款。晋升必须经项目负责人确认。一次失败不要写成长期规则。
3. **Prune（修剪）**：发现本文件、`STATE.md` 里有失效、重复、冲突或不再适用的指导时，先在 `DECISIONS.md` 追加 `N-xxx`，写清失效原因和替代结论，再删除或替换入口文件中的旧条款。不要只追加一条新规则而留下旧规则。

可选体检（非默认依赖）：在规则明显膨胀或与代码不一致时，可由项目负责人决定是否运行 `npx unrot check`。

## 工具适配（只做薄包装，规则本体只维护这一份）

- Claude Code：若需要 `CLAUDE.md`，只写 `@AGENTS.md`，Claude 专用补充写在导入之后。不要另写一套会覆盖本文件的完整规则。

- 其他支持 AGENTS.md 的工具：直接读本文件。
